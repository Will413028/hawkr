# Directory Architecture

日期：2026-05-22

這份文件是 Hawkr Web 的目錄邊界規則。判斷順序固定為：

1. 是路由入口嗎？放 `app/`。
2. 是產品功能自己的畫面、流程、元件或 hook 嗎？放 `features/<domain>/`。
3. 是無業務語意的 UI primitive 嗎？放 `components/ui/`。
4. 是跨 feature 共用、但帶 Hawkr 產品語意的 UI 嗎？放 `components/shared/`。
5. 是非 React 的資料、API、domain、config、utility 嗎？放 `lib/`。
6. 是會被 TypeScript import 的資產嗎？放 `assets/`。
7. 是瀏覽器用 URL 直接讀取的靜態檔嗎？放 `public/`。
8. 是全域 CSS 或還沒 Tailwind 化的 legacy CSS 嗎？放 `styles/`。

## Current Top-Level Ownership

```txt
app/          Next.js App Router boundary only
assets/       module assets imported by TS/TSX, currently fonts
components/   cross-app React UI
features/     product feature modules and route-facing screens
lib/          infrastructure, repositories, hooks, config, utilities
public/       browser-addressable static files
styles/       Tailwind entry, design tokens, legacy/global CSS
```

## App

`app/` owns routing, metadata, route handlers, and layout boundaries.

Allowed:

- `page.tsx`
- `layout.tsx`
- `loading.tsx`
- `route.ts`
- route params/search params parsing
- import a feature screen/page

Not allowed:

- large client components
- business workflow state
- product cards, modals, forms, tables
- route-local component folders
- static assets

Preferred route file:

```tsx
import CartPage, { metadata } from "@/features/cart/CartPage";

export { metadata };
export default CartPage;
```

## Assets

`assets/` is for files imported by TypeScript and bundled by the app.

Current structure:

```txt
assets/
  fonts/
```

Rules:

- Fonts belong in `assets/fonts/*`.
- New imported SVG/JSON/media modules should live under `assets/<type>/`.
- Do not put URL-served images here.
- Do not duplicate anything already available under `public/`.

## Components

`components/ui/` contains generic UI primitives:

- `Button`
- `Card`
- `Dialog`
- `Input`
- `Tabs`
- `ImageUploader`

`components/shared/` contains app-level Hawkr UI used by multiple features:

- `BrandLogo`
- `IconAsset`
- `AppIcon`
- `Navbar`
- `Footer`
- `ProductCard`
- `SellerPageShell`

Rules:

- Feature-only UI stays in `features/<domain>/components`.
- Shared components may import `components/ui`, `lib`, and `assets`.
- `components/ui` should not import from `features`.

## Features

`features/` owns domain screens and product workflows.

Recommended shape:

```txt
features/<domain>/
  index.ts
  screens/
  components/
  hooks/
  adapters/
  types.ts
```

Rules:

- `features/<domain>/screens` contains route-facing screens.
- `features/<domain>/components` contains feature-local UI.
- Feature hooks can live in `features/<domain>/hooks` when they are not shared.
- Cross-feature UI should be promoted to `components/shared`.

## Lib

`lib/` is infrastructure and cross-cutting runtime code. Root `lib/` is
navigation only; files live in owned subfolders.

Current structure:

```txt
lib/
  api/
  auth/
  cart/
  config/
  content/
  hooks/
  media/
  server/
  services/
  theme/
  utils/
  <domain>/
```

Allowed:

- API clients and repositories
- domain parsers and mappers
- auth/session providers and storage helpers
- config/env
- server-only auth/session helpers
- shared hooks during migration
- public URL manifests such as `lib/media/public-assets.ts`
- pure utilities

Not allowed:

- React UI components or screen composition
- CSS
- image assets
- new root-level `lib/*.ts` files
- imports from `app/`, `features/`, or `components/`

## Public

`public/` is for files intentionally exposed by URL:

```txt
public/
  brand/
  placeholders/   # generated by `pnpm gen:placeholders`; do not edit by hand
  data/
```

Rules:

- Use `/brand/...`, `/placeholders/...` when a browser URL is required.
- Do not import JSON from `public/`.
- Photos, illustrations and screenshots are not shipped; their frames show the generated SVGs in `public/placeholders/` (table in `scripts/gen-placeholders.ts`).

## Styles

`styles/globals.css` is the CSS manifest and Tailwind entry.

Current structure:

```txt
styles/
  globals.css
  foundation/
  components/
  features/
  legacy/
```

Rules:

- New UI should prefer Tailwind utilities and token-backed components.
- `styles/foundation` owns global tokens, reset, and theme bridge.
- `styles/components` and `styles/features` are migration holding areas.
- CSS files should live under `styles/`; feature/component folders should
  migrate styles here before Tailwind conversion.
- New large feature CSS files need a migration note and should be avoided.

## Duplicate Folder Policy

Do not create parallel folders for the same asset type.

Use these single sources:

| Type | Source of truth |
| --- | --- |
| Placeholder images | `public/placeholders` (generated) |
| UI icons | `AppIcon` + `@hawkr/icons` |
| Brand logos | `public/brand` + `BrandLogo` |
| UI primitives | `components/ui` |
| Cross-feature UI | `components/shared` |
| Feature-only UI | `features/<domain>/components` |
| API/repository logic | `lib/<domain>` or `lib/api` |
