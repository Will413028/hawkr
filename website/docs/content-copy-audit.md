# Hawkr Web 文案與頁面內容盤點

Last updated: 2026-05-12

這份文件的用途不是把所有 JSX 字串逐字搬出來，而是建立一個可設計、可討論、可逐頁補齊的「文案地圖」。每頁都用同一套欄位檢查：使用者來這頁要完成什麼、目前頁面有什麼內容、文案應該補哪些決策資訊。

## 文案設計方法

每個頁面先回答 5 個問題：

1. 使用者此刻的任務是什麼？
2. 這頁第一眼要讓他知道什麼？
3. 他做決策前需要哪些證據？
4. 他下一步要按哪個 CTA？
5. 如果沒有資料、失敗、未登入，要怎麼說才不讓人卡住？

建議每頁固定維護這些文案欄位：

| 欄位 | 用途 | 建議寫法 |
| --- | --- | --- |
| SEO title | 搜尋結果與瀏覽器標題 | `頁面主題 | Hawkr`，商品/商家頁用真實名稱 |
| meta description | 搜尋摘要 | 80-120 字，說明內容、價值、主要品類 |
| eyebrow | 區塊小標 | 用分類或任務，例如 `Hawkr 市集 / 商品` |
| H1 | 第一眼定位 | 直接講頁面目的，不要抽象口號 |
| intro | 協助理解頁面 | 1-2 句，說明這裡能完成什麼 |
| primary CTA | 主要動作 | 動詞開頭：看商品、加入購物車、確認下單 |
| secondary CTA | 次要動作 | 回上一頁、看更多、聯絡客服 |
| trust copy | 消除疑慮 | 配送、退貨、認證、評價、付款安全 |
| empty state | 無資料時 | 說明原因 + 下一步 |
| error state | 失敗時 | 具體說明發生什麼 + 可恢復動作 |
| form hint | 表單輔助 | 說明格式、用途、限制，不只寫「請輸入」 |

參考其他電商做法：

- 商品列表頁要顯示結果數、提供常用排序，並用「載入更多」取代傳統分頁或無限捲動；排序至少要有價格、評分、熱銷、新上架。
- 商品頁要快速回答：這是什麼、多少錢、多久到、可不可以退、為什麼可信。商品描述要包含規格、用途、好處、證據與故事。
- 結帳流程要線性、可預期；錯誤訊息要具體、靠近欄位，失敗後不可清空使用者已填資料。
- 表單 label 要保留，placeholder 只做範例；錯誤要說明怎麼修。

## Recommended Copy System

### 商品卡

固定欄位：

- 商品名：`品種/產地 + 商品 + 規格`
- 商家/產地：`商家名 · 縣市鄉鎮`
- 價格：特價時顯示現價 + 原價
- 標籤：最多 2-3 個，來源要是真資料，例如 `#當季`、`#冷藏配送`
- CTA：列表用 icon 或 `加入`，PDP 用 `加入購物車` / `立即購買`

### 商品詳細頁

建議區塊順序：

1. 商品名、品類 breadcrumb
2. 圖片與溫層
3. 價格 / 特價 / 規格 / 數量
4. 到貨與配送方式
5. 評價與標章
6. 商品描述：口感、用途、保存、規格、產地故事
7. 退換貨與售後
8. 評價 / 你可能也喜歡

### 結帳流程

每一步都要有「短標題 + 必要提示」：

- 收件地址：這會用於配送與物流通知
- 配送方式：顯示時間、溫層、費用
- 付款方式：顯示安全與跳轉說明
- 訂單摘要：商品小計、運費、優惠、總計
- 錯誤：說明哪個欄位錯、如何修、保留已填資料

### 空狀態模板

```
標題：目前沒有 {資料}
說明：{為什麼會空 / 使用者可以期待什麼}
CTA：{下一步}
```

範例：

- `目前沒有符合條件的商品`
- `換個分類、排序或關鍵字再試一次。`
- CTA：`清除篩選`

### 錯誤狀態模板

```
標題：{動作}失敗
說明：{具體原因，如果拿得到}
CTA：重新嘗試 / 聯絡客服 / 返回上一頁
```

避免：

- `發生錯誤`
- `Invalid input`
- 清空表單後叫使用者重填

## Priority Cleanup

1. 修正 FAQ header 英文：現在是 `Return and Exchange Policy`，應為 `Frequently Asked Questions`。
2. 商品列表補結果數與目前篩選摘要。
3. PDP 補「配送/退貨/保存」信任文案，放在加入購物車附近。
4. 結帳錯誤訊息細分，不只 `下單失敗，請再試一次`。
5. 商品卡標籤目前多處硬寫 `#當季`、`#冷藏配送`，應改成 hashtag / deliveryTemp 真實資料。
6. `/products/[id]` 與 `/sellers/[id]/products/[pid]` 收斂成同一份 PDP 文案架構。
7. 賣家 landing 補費用、審核、收款、物流、售後流程。

## Reference Notes

- Baymard: 商品列表應顯示商品數、使用 Load More、提供常用排序；搜尋要支援非商品名稱的需求式查詢。
- Baymard: 結帳應線性、錯誤訊息要具體可修、不要清空使用者輸入。
- Shopify: 商品描述應說明規格、用途、好處、證據與故事，並要容易掃讀。
- Shopify SEO: 商品頁要清楚傳達商品是什麼、價格、配送速度，商品名稱通常應是 H1。
