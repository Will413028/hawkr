# 買家 App 元件庫

`lib/main_catalog.dart` 是獨立的 Flutter 入口，直接使用正式元件與 `AppTheme.light`。不啟動 Firebase、登入、API、推播或分析服務。範例的商品、價格、數量與操作結果都是本地展示資料。

## 啟動與 Web Storybook 整合

```bash
# 優先使用專案 .fvm/flutter_sdk，否則使用 PATH 中的 flutter
bash scripts/component-catalog.sh run
bash scripts/component-catalog.sh test
bash scripts/component-catalog.sh build
```

建置結果為 `build/catalog/`，預設 base href 是 `/flutter/buyer/`。將整個輸出目錄放入 Web Storybook 靜態資料夾的 `flutter/buyer/`，才能保留 assets 與 CanvasKit 相對路徑。Web runtime 檔案使用本地建置資源；Flutter 的瀏覽器字型 fallback 仍由 Flutter 自身管理。

若要用一般靜態伺服器單獨查看：

```bash
CATALOG_BASE_HREF=/ bash scripts/component-catalog.sh build
python3 -m http.server 7357 --directory build/catalog
```

重新整合 Storybook 前，再執行一次預設的 `build`，恢復 `/flutter/buyer/` base href。

共同 URL 參數與賣家元件庫一致：

| 參數 | 用途 |
| --- | --- |
| `component` | 下表的固定分類 ID；未知值回到 `foundations` |
| `textScale=1.4` | 放大文字；預設 `1.0`，沿用正式 App 的 `0.8–1.4` 範圍 |
| `embedded=true` | 隱藏搜尋與分類導覽，供 Storybook iframe 使用 |

例如：`/flutter/buyer/?component=commerce&textScale=1.4&embedded=true`。分類 ID 是可分享的固定入口；目錄內點選分類與切換文字比例只改變目前預覽狀態。

## Dart API 使用範例

以下 callback 與狀態由呼叫畫面管理；元件庫不會自行登入、提交訂單或讀取後端。

### 主題、按鈕與一般輸入

買家目前以 Material 按鈕／欄位搭配共同主題，沒有名為 `AppButton` 或 `HkTextField` 的正式元件。`HkButtonLabel` 保持單行並在空間不足時省略顯示。

```dart
import 'package:hawkr_buyer/core/theme/app_theme.dart';
import 'package:hawkr_buyer/shared/widgets/hk_button_label.dart';
import 'package:flutter/material.dart';

MaterialApp(theme: AppTheme.light, home: const YourPage());

FilledButton(
  onPressed: canSubmit ? onSubmit : null,
  child: const HkButtonLabel('加入購物車'),
);

TextFormField(
  controller: nameController,
  decoration: const InputDecoration(labelText: '收件人姓名'),
  validator: (value) => value == null || value.trim().isEmpty
      ? '請填寫收件人姓名'
      : null,
);
```

### 留言、聊天與更多操作

店舖留言板、聊天輸入列、貼文留言的送出／儲存，以及 `...` 更多操作，
統一使用 `HkFrostedIconButton`。輸入列外層不再包覆整片有底色或框線的方形底板；
輸入欄位保留自己的圓角表面，圖示使用獨立圓形霧面玻璃。
更多操作使用 `AppIcons.moreHoriz` 的無方框三點圖示。

```dart
import 'package:hawkr_buyer/shared/icons/app_icons.dart';
import 'package:hawkr_buyer/shared/widgets/hk_frosted_icon_button.dart';

HkFrostedIconButton(
  label: isEditing ? '儲存編輯' : '送出留言',
  icon: isEditing ? AppIcons.check : AppIcons.send,
  onPressed: canSubmit ? onSubmit : null,
  loading: submitting,
  loadingLabel: isEditing ? '正在儲存編輯' : '正在送出留言',
  semanticHint: canSubmit ? null : '輸入留言後即可送出',
);

HkFrostedIconButton(
  label: '更多留言操作',
  icon: AppIcons.moreHoriz,
  onPressed: onOpenMenu,
);
```

必填 `label`、`icon` 與可為 null 的 `onPressed`；可選 `loading`（預設 false）、
`loadingLabel`（預設「處理中」）及 `semanticHint`。
`label` 提供 tooltip 與操作語意；表面與觸控範圍固定為 48 logical px，圖示為 24px。
停用與處理中仍保留同一個圓形霧面表面，處理中顯示進度且不能再次點按。
驗證、送出、錯誤保留草稿與焦點仍由功能畫面處理；共用按鈕不持有交易狀態。
元件庫 `buttons` 分類可同時檢查一般、停用、處理中、更多及儲存五種狀態。

非同步操作須在點擊時固定本次內容與回覆／編輯目標，處理中阻止重送及切換目標。
失敗時保留草稿與操作模式並提示錯誤；離開畫面後，延遲回應不得更新已釋放的狀態。
更多選單的取消不執行操作，編輯與回覆模式必須互斥。
操作回歸包含圓形邊緣點擊、取消按壓、鍵盤與讀屏啟動、延遲／失敗回應，
以及 `integration_test/frosted_actions_smoke_test.dart` 的隔離原生鍵盤與點擊測試。
原生測試使用正式 widget 與本機 callback，不能代替已登入帳號的後端操作驗收。

### 選擇、卡片與數量

import 'package:hawkr_buyer/shared/widgets/quantity_stepper.dart';

HkChoiceChip(

HkFrostedCardSurface(
  child: Padding(
    padding: const EdgeInsets.all(HkSpace.lg),
    child: Text(brandDescription),
  ),

HkPostCardSurface(onTap: openPost, child: postContent);

### 載入指示與骨架屏

載入動畫只有 `HkBrandLoader` 一種，動態與網頁 `BrandLogoLoader` 同一套時間軸（2600ms，遮雨棚先綻放、檯面後綻放），不要再用 `CircularProgressIndicator`。

`tone` 決定配色，規則與網頁相同：中性／淺色底用預設的 Hawkr 原色（深色底用 `brandOnDark`）；**實心品牌色表面一定要指定 `mono`、`onLight` 或 `onDark`**——原色商標疊在同色底上會完全隱形。

不給 `size` 時填滿父層（等同網頁的 `size="fit"`），呼叫端本來就有固定尺寸的盒子時用這個。

```dart
import 'package:hawkr_buyer/shared/widgets/hk_brand_loader.dart';

// 頁面或區塊置中
const HkBrandLoader(size: HkBrandLoader.page);

// 實心品牌色按鈕內，吃按鈕自己的前景色
SizedBox.square(
  dimension: HkBrandLoader.buttonLg,
  child: HkBrandLoader(
    tone: HkBrandLoaderTone.mono,
    color: scheme.onPrimary,
  ),
);
```

骨架屏的掃光統一用 `HkSkeletonShimmer` 包住色塊，參數對齊網頁 `routeLoadingSkeletonShimmer`（1.6s、白色 42% 高光）。單張圖片不要加掃光：`AppCachedImage` 預設已是靜態佔位加短淡入。

```dart
import 'package:hawkr_buyer/shared/widgets/hk_skeleton_shimmer.dart';

HkSkeletonShimmer(child: _ProductCardSkeleton());
```

## 維護方式

- 主題只有 `lib/core/theme/app_theme.dart` 一份；正式 `lib/main.dart` 與 catalog 共用。此檔案由原本 `main.dart` 的 ThemeData 原樣抽出，沒有重設品牌色、字級或按鈕規格。
- 品牌 token 保留在 `core/theme/`；目錄本身不新增另一組產品色票。
- 新的共用元件先放入正式 `shared/widgets/` 或明確的 feature widgets，再以 import 加入 `lib/catalog/component_catalog.dart`。避免在 catalog 複製一份正式元件實作。
- 新增分類時同步 `buyerCatalogSections`、搜尋詞、此表格及 Web Storybook 的 iframe story。既有深連結 ID 保持穩定。
- ScreenUtil 寬高與文字縮放維持停用；版面用 constraints 重排，文字比例使用正式 `AppMediaQueryPolicy`。

## 驗證與範圍

`test/catalog/component_catalog_test.dart` 啟動實際 catalog 入口，驗證搜尋、按鈕回呼、必填欄位、篩選、數量邊界，以及所有分類在 320 / 390 / 768px、1.0 / 1.4 倍文字下不發生 layout exception。測試會實際 layout 畫面下方的範例，並捲動至下方。

這是共用基礎元件與代表性交易元件的可執行目錄。登入、付款、聊天室、訂單等完整 feature 畫面未在目錄內接入服務；元件範例不能當作後端或付款流程的執行證據。跨 App / Web 的品牌 token 可統一比對，原生字型與各平台既有角色差異仍需依共同規格逐項處理。

### 購物車文字層級（2026-09-12）

購物車局部使用 `CartTypography`，由 `AppTypography` 的語意角色 `copyWith` 延伸，保留 Hawkr 品牌字體與顏色。22／28 是 Material 3 `titleLarge` 的購物車區塊適配，24／32 是 `headlineSmall` 的總額適配；並非把 Apple 或 Android 的整套數值套用到全 App，也不更動全域 token ramp。

| 用途 | 基準字級／行高 | 字重 |
| --- | --- | --- |
| 購物車頁面標題，以及寄送方式、交易備註、付款詳情等區塊標題 | 22／28 | 600 |
| 總付款金額數字 | 24／32 | 600 |
| 品名、商家名、配送名稱、單價 | 16／24 | 600 |
| 正文與明細標籤 | 16／24 | 400 |
| 規格、收件資料與輔助資訊 | 14／20 | 400 |
| 文字按鈕與數量數字 | 16／24 | 600 |

頂部導覽標題沿用同一個 22／28 標題角色；購物車透過 `QuantityStepper.countTextStyle: CartTypography.button` 套用 16／24 數量文字。這個可選 `TextStyle?` 參數未提供時仍維持共享步進器原有 20px 數字角色，其他畫面不受影響；加減圖示與 48px 觸控範圍不變。冷藏／冷凍／常溫改用下方 Web 對齊的 `HkTemperatureTag` 獨立 11px 角色，不接受購物車局部 typography 覆寫。

`CartTopBar({required VoidCallback onBack, required Widget chatAction, VoidCallback? onClear})` 是正式頁面與預覽共用的購物車導覽列。標題使用「購物車」與 22／28 字體，`NavigationToolbar` 為返回、清空與訊息保留原 48px 範圍，避免窄版大字時標題與右側操作重疊；`onClear` 未提供時不顯示清空按鈕。預覽的三個回呼只記錄次數，不執行導航或清空真實資料。

字體小／中／大仍使用正式 `AppTextSize` 與 `AppMediaQueryPolicy`，不新增產品端設定；`?component=cart&textSize=small|standard|large` 與 catalog 上方切換僅預覽該現有政策。測試涵蓋 320／390px、系統 1.0／1.4×，檢查三種偏好、持久化還原、字級與行高角色、Web 溫層樣式及至少 48px 觸控範圍。


## 配送溫層標籤與 Web 對齊

`HkTemperatureTag(value:)` 是商品詳情、快速加入購物車、購物車商品與配送選項、訂單列表、訂單詳情及退貨收件資訊的共同顯示元件。以 API 提供的溫層顯示，不為沒有資料的商品推定溫層。`3201`／`AMBIENT`／`常溫`、`3202`／`CHILLED`／`冷藏`、`3203`／`FROZEN`／`冷凍` 會轉成中文；未知值保留原文並採中性灰，空值不顯示。

視覺對齊 Web `features/cart/components/TemperatureTag.tsx`：常溫 `#6B6B6B`、冷藏 `#EE964B`、冷凍 `#51A2FF`，透明底、同色 1dp 外框、全圓角、左右 8dp、11dp 粗體、不加圖示或字距。標準文字比例的高度為 18dp；Flutter 以 16dp 文字行高加兩側邊框保留完整字形，隨系統與既有小／中／大文字設定自然增高。

並列標籤採 Wrap 與 4dp 間距。分類篩選的 `TemperatureChoiceChip` 仍是獨立可互動控件，保留選取狀態和至少 48dp 的實際點擊區；資訊標籤本身不新增按鈕語意。`?component=chips` 提供三種已知溫層、未知值與選擇器的正式元件示例。


### 購物車店家選取範圍（2026-09-12）

商店入口與選取控制拆成兩列，每店明示「選取本店可購買商品」與已選／可購買項目數。選另一店時顯示「改選本店可購買商品」及「切換結帳店家，原店商品保留」；原店商品不會刪除，無法購買的商品仍顯示於清單且不勾入結帳。結帳區顯示本次商店名稱與已選項目數，未選取時停用，沒有跨店結帳或全域全選入口。

App 原本沒有常駐重新整理操作；錯誤重試仍保留。背景更新保留使用者取消選取的結果；只有初次載入會沿用原本預選第一店的行為，指定商品入口仍可預選該商品。切店立即清空驗證與配送快照並停用結帳，忽略舊店晚回來的驗證、運費與失敗回應；地址／門市刷新只合併最新狀態，結帳券取自本次選取商品。`CartState.checkoutPending` 統一阻擋購物車刷新、數量寫入、商品驗證及運費精算未完成時的點按／上滑結帳。

`?component=cart` 使用兩間商店、一筆不可購買商品與固定配送資料，可操作切店、取消和數量；預覽不連接真實帳戶／API。單店規則與延遲回應使用正式 `CartController` 測試，widget 測試涵蓋 320／390px 與 1.4×、勾選可購買商品、結帳商店名稱與停用時點按／上滑。溫層標籤採上述共用 Web 樣式。

### 購物車緊湊排列（2026-09-12）

店家標頭右側以「賣家商店」明示導覽，與店名共用同一列，地點仍可完整換行；店內勾選維持獨立範圍。手機商品將原有單價／庫存與數量放到縮圖旁，完整品名、規格及原溫層不擠入窄欄。數量維持既有 48px 觸控與文字縮放，窄版多位數時改由品名旁承接勾選，避免縮圖或數量互相擠壓。`?component=cart` 使用正式元件展示此排列。

緊湊購物車在數量較長、縮圖與 48px 控制項無法同列時，會把數量移至下一列；若數量本身超過可用寬度，採 `QuantityStepper(stacked: true)` 讓完整數字顯示於按鈕上方並自然換行，不縮小文字或點擊範圍。不可購買商品的狀態標籤使用正常排列，不覆蓋品名或規格。
