## 1. 新增枚舉

### 1.1 PaymentTransactionStatus（新增）

**檔案**: `PaymentTransactionStatus.java`

**用途**: 支付交易內部狀態（支付服務專用）

| code | value | dbValue | displayName | description |
|------|-------|---------|-------------|-------------|
| INIT | 0 | 0 | 待付款 | 交易建立完成，等待付款 |
| PAID | 1 | 1 | 已付款 | 付款成功 |
| FAILED | 2 | 2 | 付款失敗 | 付款未成功 |
| EXPIRED | 3 | 3 | 已逾期 | 逾期未付款 |
| CONFLICT | 4 | 4 | 狀態衝突 | 同步與 Webhook 結果不一致，需人工介入 |
| CLOSED | 5 | 5 | 已關閉 | 交易主動關閉 |

**狀態轉換規則**:
- INIT → PAID: 付款成功
- INIT → FAILED: 付款失敗
- INIT → EXPIRED: 逾期未付款
- INIT → CONFLICT: 狀態衝突
- INIT → CLOSED: 主動關閉

**終態**: PAID, FAILED, EXPIRED, CONFLICT, CLOSED

### 1.2 RefundStatus（新增）

**檔案**: `RefundStatus.java`

**用途**: 退款交易狀態

| code | value | dbValue | displayName | description |
|------|-------|---------|-------------|-------------|
| REQUESTED | 0 | 0 | 申請中 | 退款申請已建立 |
| PROCESSING | 1 | 1 | 處理中 | PayUni 處理中 |
| SUCCEEDED | 2 | 2 | 退款成功 | 退款已完成 |
| FAILED | 3 | 3 | 退款失敗 | 退款未成功，需人工介入 |

**狀態轉換規則**:
- REQUESTED → PROCESSING: PayUni 接受退款
- REQUESTED → FAILED: PayUni 拒絕退款
- PROCESSING → SUCCEEDED: 退款成功
- PROCESSING → FAILED: 退款失敗

**終態**: SUCCEEDED, FAILED

---

### 1.3 OutboxStatus（新增）

**檔案**: `OutboxStatus.java`

**用途**: Outbox 事件發送狀態

| code | value | dbValue | displayName | description |
|------|-------|---------|-------------|-------------|
| PENDING | 0 | 0 | 待發送 | 事件等待發送 |
| SENT | 1 | 1 | 已發送 | 事件發送成功 |
| FAILED | 2 | 2 | 發送失敗 | 發送失敗，等待重試 |
| DEAD | 3 | 3 | 死信 | 超過最大重試次數，需人工處理 |

**狀態轉換規則**:
- PENDING → SENT: 發送成功
- PENDING → FAILED: 發送失敗
- FAILED → SENT: 重試成功
- FAILED → DEAD: 超過最大重試次數

**終態**: SENT, DEAD

| REFUND_FAILED | refund.failed | 退款失敗 | 退款處理失敗 |

## 2. 修改枚舉

### 2.1 PaymentMethod（修改）

**檔案**: `PaymentMethod.java`

**變更內容**:
1. 新增 `dbValue` 欄位，用於資料庫 SMALLINT 映射
2. 新增 `dbValue()` 方法
3. 新增 `fromDbValue(int)` 靜態方法
4. 移除舊的 `ATM_TRANSFER` 和 `CASH_ON_DELIVERY`
5. 新增 `ATM` 和 `CVS`
6. 調整 value 順序以配合資料庫定義

**新的枚舉值定義**:

| code | value | dbValue | displayName | description |
|------|-------|---------|-------------|-------------|
| CREDIT_CARD | 2001 | 1 | 信用卡 | 信用卡一次付清 |
| APPLE_PAY | 2002 | 2 | Apple Pay | Apple 行動支付 |
| GOOGLE_PAY | 2003 | 3 | Google Pay | Google 行動支付 |
| ATM | 2004 | 4 | ATM 轉帳 | 銀行虛擬帳戶轉帳 |
| CVS | 2005 | 5 | 超商代碼 | 超商代碼繳費 |
| LINE_PAY | 2006 | 6 | LINE Pay | LINE 行動支付 |

**注意**:
- `dbValue` 對應資料庫 `payment_transactions.payment_type` 欄位
- 原有的 `ATM_TRANSFER` 已改為 `ATM`
- 原有的 `CASH_ON_DELIVERY` 已移除（PayUni 不支援）

## 5. 影響範圍

### 需要更新的文件
- 枚舉統一管理文件
- API 文件（Proto 枚舉定義）
- 資料庫設計文件

### 需要注意的相容性
- `PaymentMethod` 的變更可能影響使用該枚舉的其他服務
- 如有服務使用 `ATM_TRANSFER`，需改為 `ATM`
- 如有服務使用 `CASH_ON_DELIVERY`，需移除相關邏輯
