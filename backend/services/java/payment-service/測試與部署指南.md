# Payment Service 測試與部署指南

## 1. 資料庫設置

### 1.1 建立資料庫

Payment Service 使用 PostgreSQL 資料庫。請先建立資料庫：

```sql
-- 連接到 PostgreSQL
psql -U postgres

-- 建立資料庫
CREATE DATABASE payment;

-- 建立使用者（可選）
CREATE USER payment_user WITH PASSWORD 'your_password';
GRANT ALL PRIVILEGES ON DATABASE payment TO payment_user;
```

### 1.2 表格建立（Flyway 自動執行）

**不需要手動建立表格**。Payment Service 使用 Flyway 進行資料庫遷移，啟動時會自動執行：

- 位置：`src/main/resources/db/migration/V1__init_payment_tables.sql`

若需手動執行，可使用以下 DDL：

```sql
-- 連接到 payment
\c payment

-- 執行遷移腳本
\i /path/to/V1__init_payment_tables.sql
```

### 1.3 表格結構說明

| 表格名稱 | 說明 |
|---------|------|
| `payment_transactions` | 支付交易主表 |
| `payment_refunds` | 退款記錄表 |
| `payment_webhooks` | Webhook 記錄表 |
| `payment_outbox` | Outbox 事件表 |
| `payment_logs` | 操作日誌表 |

## 2. 統一金流（PayUni）配置

### 2.1 環境變數配置

```bash
# PayUni 商家資訊（請向 PayUni 申請）
PAYUNI_MERCHANT_ID=your_merchant_id        # 商家編號
PAYUNI_MERCHANT_KEY=your_32_char_key       # 32 字元金鑰（AES-256）
PAYUNI_MERCHANT_IV=your_16_char_iv         # 16 字元 IV

# PayUni API 端點
# PAYUNI_API_URL=https://api.payuni.com.tw   # 正式環境
PAYUNI_API_URL=https://sandbox-api.payuni.com.tw  # 測試環境

# 回調 URL（PayUni 通知用）- 直接到 Payment Service，不經 Gateway
PAYUNI_NOTIFY_URL=https://your-domain.com:9924/webhook/payuni/notify
PAYUNI_RETURN_URL=https://your-domain.com/payment/result
```

### 2.2 PayUni 測試帳號（沙盒環境）

若使用 PayUni 沙盒環境測試，請向 PayUni 申請測試商家帳號。

### 2.3 application.yml 配置範例

```yaml
payuni:
  merchant:
    id: ${PAYUNI_MERCHANT_ID}
    key: ${PAYUNI_MERCHANT_KEY}
    iv: ${PAYUNI_MERCHANT_IV}
  api:
    base-url: ${PAYUNI_API_URL:https://sandbox-api.payuni.com.tw}
  callback:
    notify-url: ${PAYUNI_NOTIFY_URL}
    return-url: ${PAYUNI_RETURN_URL}
```

## 3. Webhook 配置

### 3.1 Webhook 端點

Payment Service 提供以下 Webhook 端點供 PayUni 回調：

| 端點 | 方法 | 說明 |
|------|------|------|
| `/webhook/payuni/notify` | POST | PayUni 付款結果通知 |
| `/webhook/payuni/health` | GET | 健康檢查（內網） |

### 3.2 Webhook 請求格式

PayUni 以 `application/x-www-form-urlencoded` 格式發送：

```
MerID=商家編號
Version=API版本
EncryptInfo=加密資料
HashInfo=簽章
```

### 3.3 在 PayUni 後台設定

1. 登入 PayUni 商家後台
2. 進入「API 設定」→「通知網址設定」
3. 設定 NotifyURL：`https://your-domain.com/webhook/payuni/notify`

### 3.4 本地測試 Webhook（使用 ngrok）

```bash
# 1. 啟動 Payment Service
(cd .. && ./mvnw spring-boot:run -pl :payment-service)

# 2. 使用 ngrok 建立通道
ngrok http 9924

#安裝：brew upgrade ngrok

# 3. 將 ngrok URL 設定為 PayUni NotifyURL
# 例如：https://abc123.ngrok.io/webhook/payuni/notify
```

## 4. Gateway 串聯配置

### 4.1 環境變數配置

在 Gateway 的環境變數中新增：

```bash
# Payment Service 配置
PAYMENT_JAVA_SERVICE_HOST=127.0.0.1
PAYMENT_JAVA_SERVICE_PORT=9924           # HTTP 端口（Webhook）
PAYMENT_JAVA_SERVICE_GRPC_PORT=9925      # gRPC 端口
```

### 4.2 Gateway 路由配置

需要在 Gateway 中新增以下路由：

#### 方案 A：HTTP 代理（簡單，適合快速測試）

在 `gateway/internal/proxy/reverse_proxy.go` 中新增：

```go
var services = map[string]ServiceConfig{
    // ... 既有服務 ...

    "payment-java": {
        Name:   "payment-java",
        Host:   getEnvOrDefault("PAYMENT_JAVA_SERVICE_HOST", "127.0.0.1"),
        Port:   getEnvOrDefault("PAYMENT_JAVA_SERVICE_PORT", "9924"),
        Prefix: "",
    },
}
```

#### 方案 B：gRPC 客戶端（推薦，正式環境）

需要：
1. 將 `payment.proto` 編譯為 Go 代碼
2. 建立 gRPC 客戶端
3. 新增 handler 處理請求

### 4.3 Gateway 路由定義

在 `gateway/internal/router/routes.go` 中新增（HTTP 代理方案）：

```go
// Payment Service (Java) 路由
paymentJava := v1.Group("/payment")
paymentJava.Use(middleware.JWTAuth())
{
    // 建立支付
    paymentJava.POST("/create", proxy.CreateProxy("payment-java"))
    // 查詢支付
    paymentJava.GET("/:tradeNo", proxy.CreateProxy("payment-java"))
    // 同步狀態
    paymentJava.POST("/:tradeNo/sync", proxy.CreateProxy("payment-java"))
    // 關閉交易
    paymentJava.POST("/:tradeNo/close", proxy.CreateProxy("payment-java"))
    // 退款
    paymentJava.POST("/refund", proxy.CreateProxy("payment-java"))
}

// Webhook（公開，來自 PayUni）
callbacks := r.Group("/webhook")
{
    callbacks.POST("/payuni/notify", proxy.CreateProxy("payment-java"))
}
```

## 5. 啟動服務

### 5.1 啟動 Payment Service

```bash
cd services/java/payment-service

# 設定環境變數
export DB_HOST=localhost
export DB_PORT=5432
export DB_NAME=payment
export DB_USERNAME=postgres
export DB_PASSWORD=your_password

export PAYUNI_MERCHANT_ID=your_merchant_id
export PAYUNI_MERCHANT_KEY=your_32_char_key
export PAYUNI_MERCHANT_IV=your_16_char_iv
export PAYUNI_API_URL=https://sandbox-api.payuni.com.tw
export PAYUNI_NOTIFY_URL=http://localhost:9924/webhook/payuni/notify
export PAYUNI_RETURN_URL=http://localhost:3000/payment/result

# 啟動服務
(cd .. && ./mvnw spring-boot:run -pl :payment-service)

# 或使用 IDE 啟動
```

### 5.2 驗證服務啟動

```bash
# HTTP 健康檢查
curl http://localhost:9924/webhook/payuni/health

# gRPC 服務（使用 grpcurl）
grpcurl -plaintext localhost:9925 list
```

## 7. 直接測試（不經 Gateway）

若要直接測試 gRPC 服務，可使用 `grpcurl`：

### 7.1 安裝 grpcurl

```bash
# macOS
brew install grpcurl

# Linux
go install github.com/fullstorydev/grpcurl/cmd/grpcurl@latest
```

### 7.2 列出服務

```bash
grpcurl -plaintext localhost:9925 list
```

### 7.3 呼叫方法

```bash
# 建立支付
grpcurl -plaintext -d '{
  "order_id": "ORD001",
  "payment_type": "PAYMENT_TYPE_CREDIT_CARD",
  "amount": 10000,
  "product_name": "測試商品"
}' localhost:9925 io.github.will413028.hawkr.payment.grpc.PaymentService/CreatePayment

# 查詢支付
grpcurl -plaintext -d '{
  "trade_no": "TRD202402041234560001"
}' localhost:9925 io.github.will413028.hawkr.payment.grpc.PaymentService/GetPayment
```

## 8. 常見問題

### 8.1 無法連接資料庫

```
確認 PostgreSQL 正在運行：
  pg_isready -h localhost -p 5432

確認資料庫存在：
  psql -U postgres -c "\l" | grep payment
```

### 8.2 PayUni 簽章驗證失敗

```
1. 確認 MERCHANT_KEY 為 32 字元
2. 確認 MERCHANT_IV 為 16 字元
3. 確認使用正確的環境（正式/測試）
```

### 8.3 gRPC 連接失敗

```
確認 gRPC 端口已開啟：
  nc -zv localhost 9925

確認服務已啟動：
  curl http://localhost:9924/webhook/payuni/health
```
