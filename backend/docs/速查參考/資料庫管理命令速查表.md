# 資料庫管理命令速查表

> 本機資料庫跑在 Docker（OrbStack），本地開發的唯一入口是專案根目錄的 `./dev.sh`。
> 資料庫清單的唯一真實來源是 `scripts/init-databases.sh` 的 `DATABASES` 陣列。

## 🚀 快速開始（最常用）

```bash
# 啟動本地環境（順便補建缺少的資料庫）
./dev.sh up

# 套用 Go 服務 schema + 匯入測試資料
./dev.sh seed
```

`./dev.sh up` 會在 postgres 容器內重跑 `scripts/init-databases.sh`（冪等，只建缺的，不動既有資料）。
Java 服務的 schema 由各服務啟動時的 Flyway 自動套用，沒有對應的手動命令。

⚠️ `./dev.sh seed` 會 **DROP 並重建**所有 Go 服務的資料庫，本機這些庫的資料會全部消失。

## 📋 完整命令列表

### Makefile（專案根目錄）

| 命令 | 說明 |
|------|------|
| `make db-init` | 建立所有資料庫（`make db-init-local` 為同一目標，內部呼叫 `./scripts/init-databases.sh local`） |
| `make atlas-validate-all` | 離線驗證所有單體模組與舊服務的 migration 目錄完整性（CI：backend-db-proto-checks）（`atlas.sum` 與檔案對得上），不需連 DB |

`make db-init` 是在 host 上跑 `psql`，需要本機裝有 PostgreSQL client，且密碼要由環境變數提供：

```bash
DB_PASSWORD=Hawkr2024Admin make db-init
```

本機沒裝 `psql` 時不需要這條 —— `./dev.sh up` 已經在容器內做完同一件事。

### dev.sh（本地開發入口）

| 命令 | 說明 |
|------|------|
| `./dev.sh up` | 啟動基礎設施與所有服務，並補建缺少的資料庫 |
| `./dev.sh seed` | 重建 Go 服務資料庫 → `atlas migrate apply` → 匯入測試資料 → 重啟這些服務 |
| `./dev.sh restart <服務>` | 重啟單一服務（Java 服務加了 Flyway migration 後用它看 migrate log） |
| `./dev.sh down` | 停止全部服務（保留資料 volume） |

要連 postgres 的 data volume 一起清掉：

```bash
docker compose -f docker-compose-local.yml down -v
```

⚠️ `./dev.sh down` 不轉傳參數，`./dev.sh down -v` 的 `-v` 會被無聲忽略，volume 不會被清掉。

## 📊 常見工作流程

### 1. 新機器初始設定
```bash
git clone <repo>
cd backend-payuni
./dev.sh up      # 首次啟動時 postgres init script 會建好所有資料庫
./dev.sh seed    # Go 服務 schema + 測試資料
```

### 2. Pull 新程式碼後
```bash
git pull
./dev.sh seed      # Go 服務：套用新的 Atlas migration（會重建這些庫）
./dev.sh rebuild   # Java 服務：重建有變更的服務，啟動時 Flyway 自動 migrate
```

### 3. 本地資料壞掉想重來
```bash
# 只重來 Go 服務的庫
./dev.sh seed

# 全部清掉（含 Java 服務的庫）
docker compose -f docker-compose-local.yml down -v
./dev.sh up
./dev.sh seed
```

### 4. 新增 Migration（Go 服務 / Atlas）

`db/schema/schema.sql` 是唯一真實來源，migration 一律由 Atlas 產生，禁止手寫。

```bash
# 1. 編輯 schema
vim services/review-service/db/schema/schema.sql

# 2. 產生 migration（互動輸入 migration 名稱）
cd services/review-service && make migrate-diff

# 3. 重算 checksum（漏了 CI 直接紅）
cd db && atlas migrate hash

# 4. 回專案根目錄套用到本地並測試
cd ../../..
./dev.sh seed
(cd services/review-service && go test ./...)
```

⚠️ 各服務 `atlas.hcl` 只定義 `dev` / `prod` 兩個 env（**沒有 `local`**），它們連的是共用的遠端資料庫。因此：`make migrate-status`（唯讀）可用；**禁止**手動執行 `make migrate-apply` 或任何對 dev / prod 的 `atlas migrate apply`，遠端 migration 一律由 CI/CD 的 migrate job 套用。

### 5. 新增 Migration（Java 服務 / Flyway）

`V1__init_*.sql` 已凍結，變更一律新增 `V{N+1}__{verb}_{target}.sql`（禁止跳號）。本地 `./dev.sh restart <服務>` 看 Flyway log 驗證後 push，遠端由 CI/CD 自動套用。規則見 [PostgreSQL 設計規範與最佳實踐](../開發規範/PostgreSQL%20設計規範與最佳實踐.md)、[DB Migration 相容性規範（expand-contract）](../開發規範/DB%20Migration%20相容性規範（expand-contract）.md) 與 [38-Flyway 自動同步與 DB 自動初始化](../詳細設計書/38-Flyway%20自動同步與%20DB%20自動初始化（Flyway%20Auto%20Sync%20&%20DB%20Auto%20Init）詳細設計書.md)。

## 🎯 環境說明

### Local（本地開發）
- Host: `localhost:5432`（容器 `hawkr-postgres`，`postgres:17-alpine`）
- 帳號: `dbadmin`，密碼見 `docker-compose-local.yml`
- 影響: 只有你自己，可以隨意重設

### Dev / Prod
- 不在本表範圍。遠端 schema 變更只走 push → PR → CI/CD，禁止 SSH 手跑 DDL、禁止本機 `atlas migrate apply`。

## 🔍 除錯命令

### 查看所有資料庫
```bash
docker exec -it hawkr-postgres psql -U dbadmin -d postgres -c "\l"
```

### 連線到特定資料庫
```bash
docker exec -it hawkr-postgres psql -U dbadmin -d hawkr_review

# 在 psql 中
\dt                 # 列出所有 table
\d order_item_reviews          # 查看 table 結構
\q                  # 離開
```

### 查看 Migration 狀態（本地）
```bash
cd services/review-service/db
atlas migrate status --dir "file://migrations" \
  --url "postgres://dbadmin:REDACTED@localhost:5432/hawkr_review?sslmode=disable"
```

### 驗證 migration 目錄完整性（不需連 DB）
```bash
make atlas-validate-all
```

## 📦 涵蓋的資料庫

`scripts/init-databases.sh` 的 `DATABASES` 陣列是唯一真實來源，新增服務時改那裡；`./dev.sh up` 每次啟動都照該清單補建缺少的資料庫。

有自己 Atlas migration 的 Go 服務（其餘 Java 服務走 Flyway，不使用 Atlas）：

```bash
ls services/*/db/atlas.hcl
```

## 💡 小技巧

### 1. 只重建單一 Go 服務的資料庫
```bash
docker exec -i hawkr-postgres psql -U dbadmin -d postgres \
  -c 'DROP DATABASE IF EXISTS "hawkr_review" WITH (FORCE);'
docker exec -i hawkr-postgres psql -U dbadmin -d postgres \
  -c 'CREATE DATABASE "hawkr_review";'
cd services/review-service/db && atlas migrate apply \
  --dir "file://migrations" \
  --url "postgres://dbadmin:REDACTED@localhost:5432/hawkr_review?sslmode=disable"
```

### 2. 查看某個服務的 migration 列表與內容
```bash
ls -l services/review-service/db/migrations/
cat services/review-service/db/migrations/<timestamp>_<name>.sql
```
