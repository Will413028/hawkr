# AGENTS.md 分三層、各有上限；模組規格移到 `docs/modules/`

| 項目 | 值 |
|---|---|
| 狀態 | accepted |
| 日期 | 2026-10-28（Will 決定） |
| 影響範圍 | repo 內所有 `AGENTS.md`、`cmd/new-module` 的模板、`docs/開發規範/設計文件治理規範.md` 的文件 taxonomy、單體 ADR `2026-09-24-go-modular-monolith.md` 對模組 `AGENTS.md` 的定義 |
| 執行計畫 | `docs/plans/2026-10-28-agents-md-layering.md` |

## 脈絡

`AGENTS.md` 是 coding agent 的指令檔。Claude Code 在 session 開始時載入根目錄那份，讀到某個目錄的檔案時再載入路徑上各層的那一份（2026-10-28 實測）。2026-10-28 時，seller 模組那份有 168,637 bytes，碰 seller 任何一個檔就整份載入。原因是單體 ADR 把模組 `AGENTS.md` 定義成「職責、擁有的資料、不變量、讀取模型、不負責什麼」，結果行為規格逐條寫了進去。

約束：
- 外部：agent 的 context 有上限，指令檔每次碰目錄就整份載入（實測）。Codex 串接的合計上限預設 32KiB（Codex 文件，未在本機實測）。
- 繼承：單體 ADR 對模組 `AGENTS.md` 的定義。這是我們自己訂的，沒有外部理由，可以推翻。
- 繼承：既有的詳細設計書多半是公司時期為微服務寫的（例：設計書 08 是多媒體微服務）。它們仍然存在，但描述的不是單體的現況；有 5 個模組（accountdeletion、agent、discovery、reviewqueue、social）沒有對應的設計書。

## 考慮過的方案

| 題目 | 方案 | 代價 | 判定 |
|---|---|---|---|
| 各層放什麼 | 基準：根目錄與子專案放指令、慣例與坑，越近的越優先，要短；規格與理由放在文件裡、需要時才讀（AGENTS.md 規範 <https://agents.md>；Anthropic 對 CLAUDE.md 的建議 <https://docs.anthropic.com/en/docs/claude-code/memory>） | 模組 `AGENTS.md` 要從「說明書」縮成「改前必讀」，現有內容要搬家 | 採用：模組固定七節（職責、擁有的資料、發布的讀取介面、模組內部結構、不變量、不負責、決策紀錄指向） |
| | 保留現有的節，只限大小 | 規格還是會寫進來，只靠上限硬擋，邊界不清楚 | 否決 |
| 大小上限 | 根目錄 12,000 bytes、子專案 10,000、模組與 `packages/*` 6,000，單行 500 字元，由 CI 擋 | 根目錄的契約表要收短；最深的路徑合計 28,000 bytes 以內 | 採用 |
| | 統一 8,000 bytes | 根目錄的契約表與 backend 的單體規則都要拆檔，拆出來的又是一層間接 | 否決：拆檔的代價大於省下的 context |
| | 只限模組 | 根目錄與子專案會再長回去（根目錄 2026-10-28 時已有 20,779 bytes） | 否決 |
| 模組規格放哪 | 每個模組一份 `docs/modules/<模組>.md`，是單體模組行為規格的唯一來源 | 多一個目錄；舊設計書要標明不是現行規格 | 採用 |
| | 寫進既有的詳細設計書 | 同一份文件混著舊微服務設計與單體現況，讀的人分不清哪段有效；5 個模組沒有設計書 | 否決 |
| | Go package doc（`doc.go`） | 不適合長篇規格，不在設計文件的引用體系裡 | 否決 |
| seller 縮不到上限 | seller 拆模組另立計畫；本計畫收尾時 seller 是例外清單的唯一一項，寫明由拆模組計畫清掉 | 例外清單暫時不空，但有擁有者與關閉條件 | 採用 |
| | 拆模組併進本計畫 | 架構變更（依賴表、schema、事件），規模遠大於整理文件 | 否決 |
| | 放寬模組上限 | 等於沒有上限 | 否決 |

## 決策

- 根目錄 `AGENTS.md` 放專案地圖、跨專案契約、共通規則；子專案放指令、技術慣例、特有的坑；模組放固定七節，每條不變量是一句規則加守門測試與規格位置。
- 大小由 `scripts/check-agents-md.py` 在 CI 檢查（bytes；單行以字元計）；例外清單只能縮小。
- 單體模組的行為規格在 `docs/modules/<模組>.md`，遵守詳細設計書的規則（只寫現在的契約，不寫歷史與理由）；舊設計書在檔頭標明現行規格的位置。
- 單體 ADR 對模組 `AGENTS.md` 的定義依本 ADR 修訂。

## 理由

指令檔的成本是每次載入，文件的成本是需要時才讀；把規格留在指令檔，等於每次碰模組都付整份規格的成本，換來的只是「改程式時一定看得到」。把不變量縮成一句規則加守門測試，保住「一定看得到」，細節按需讀取。上限由 CI 擋而不是靠自律，因為這次的膨脹正是在沒有上限時一條條累積出來的。代價是一次性的搬遷工作與多一個文件目錄。

## 預期結果

- 碰任何模組時，路徑上的 `AGENTS.md` 合計不超過 28,000 bytes（seller 在拆模組完成前除外）。
- 新模組由 `make new-module` 產生的 `AGENTS.md` 只有七個固定節，`main_test.go` 守住。

## 撤銷條件

- agent 工具改成按需載入指令檔的片段（不再整份載入）時，重新評估上限。
- 規格放 `docs/modules/` 後，出現同一條規格在兩處漂移的實例時，重新評估位置。
