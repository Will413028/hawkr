## 脈絡

需求（Will 2026-10-23）：repo 公開當作品集，同時解決 private repo 的 Actions 額度（每月 2,000 分鐘；public repo 用標準 runner 免費）。舊品牌名與 logo 有商標，文案與素材不在老闆同意的範圍內（同意範圍只寫「程式碼」，Will 2026-10-18）。

約束：

- 外部：舊品牌名與 logo 有商標。
- 外部：GitHub 不能把 issue 從 private repo 移轉到 public repo。
- 外部：public repo 收 fork PR，fork 拿不到 repository secret。
- 外部：沒有自己的網域，暫不申請（Will 2026-10-23）。
- 繼承：系統從未上線，改名不受相容性約束（根目錄 `AGENTS.md`）。
- 繼承：legacy 服務預定在主計畫階段 B、C 刪除，但單體還靠它們跑沒搬完的模組。現在仍成立。

## 考慮過的方案與決策

| 題目 | 決策 | 沒選的方案與理由 |
|---|---|---|
| 歷史 | 開新 repo，只有單一初始 commit；舊 repo 改名封存為 private | 在原 repo 重寫歷史：無法保證舊 commit、fork 與快取都清乾淨 |
| 名字 | Hawkr，中英文介面都用 | 和農產品有關的名字：作品集示範的是一般電商 |
| D1 公司時期的設計書、規範與供應商文件 | 公開，清洗品牌、人名與供應商的特店資訊 | 只公開 2026-09 之後自己寫的文件：Will 選擇保留完整的設計紀錄 |
| D2 來源不明的圖片 | 品牌圖用 `brand/hawkr/`，示範圖改成程式產生的佔位 SVG | Unsplash：要逐張判斷授權；AI 生成：授權依工具條款 |
| D3 issue | 在新 repo 重建，並替換舊名與舊路徑 | 留在封存：當初搬 issue 就是為了不漏 |
| D4 反向 DNS 前綴 | `io.github.will413028.hawkr` | `dev.hawkr`：沒有這個網域，被別人註冊後就成了冒用 |
| D5 e2e | 在本階段新增 website 與 admin 的 Playwright workflow；視覺基準第一次在 CI 產生 | 延後：現況是 e2e 在本機與 CI 都沒有跑 |
| D6 兩字母縮寫 | 改成 `hk-`／`hk_` | 保留：會讓人看出舊名 |
| D7 名字類檢查（品牌、法人、同事） | 只在本機 pre-commit／pre-push 執行，讀不進版控的明文清單；CI 只跑不含名字的檢查、gitleaks 與 secret scanning | 公開未加鹽的雜湊：可以用字典反查；HMAC 加 repository secret：fork PR 會跳過，還要多管一個 secret |

## 後果

- 之後的開發在新 repo。計畫與 ADR 裡的 commit hash 指的是私人封存。
- 外部 PR 不受名字類檢查；只有 Will 一個開發者時可以接受。
- 重新評估的條件：
  - 有第二個長期貢獻者時，重評 D7。
  - 申請網域時，改掉 D4 的前綴。

## 修訂：縮寫的同族寫法與撞名的資料值（2026-10-24，Will）

步驟 1 的盤點發現，D6 列的 `<縮寫>-`／`<縮寫>_` 之外，同一個縮寫還用在 UI 元件與頁面前綴、Pascal 類別前綴、日誌類別、camelCase 識別碼，以及大寫的資料值（代行工作階段編號、header 格式、訂單與出貨單編號前綴、測試編號）。決策（計畫 D8）：全部改成 `hk` 系列，資料值的格式前綴連同產生碼、驗證正則、CHECK、種子與 fixture 一起改，migration 改寫後重算 `atlas.sum`。沒選的方案是只改程式識別碼、保留資料值：掃描要為資料值開例外清單，不能直接當「必須是 0」的關卡，而上線前也沒有相容性約束要保留舊格式。

## 修訂：計畫的後續決定併入、計畫已刪除（2026-11-15，原決定日期與決定者見各項）

執行計畫 `2026-10-24-portfolio-public` 與附件（`contrast.py`、`gen_qr.py`、`inventory.md`、`rename-map.md`、`deleted-assets.tsv`、`ci-local-map.md`）依「完成的計畫不留在 repo」的決定在 2026-11-15 刪除，git 歷史是紀錄。上方「詳細論證」原指向該計畫的規模與步驟；步驟已完成，不再保存。計畫的 D1–D8 已在本檔；D9–D13 在計畫裡才有，以下照計畫轉記（理由與未選方案取自計畫，計畫未記的不補）。以上都是 Will 的決定，原決定日期各項標明；皆不改上方決策表的結論。

- **D9 舊名中文字首的子品牌與功能名**（Will 2026-10-25，照建議選 A）：視為舊名。使用者面文字把字首換成 Hawkr（Hawkr Agent、Hawkr 幫找、Hawkr 動態、Hawkr 市集），版面不動；名字類檢查的清單加一列並計入守門。程式識別碼與路徑在素材刪完後才改，避免改名後又刪。理由：衍生名仍會讓人看出舊品牌。未選：B 改成不掛品牌的通用功能名（每處都要改寫、長度改變可能動到版面）；C 不算舊名而保留（衍生名洩漏舊品牌）。
- **D10 法律頁**（Will 2026-10-25，選 B）：八份法律文件（隱私、服務條款、退貨、使用者政策四頁，與賣家條款、KYC 告知、食品登錄告知、自行開立聲明四份 Markdown）內文都換成簡短的作品集說明（示範專案、非實際營運、不收集真實資料）；版面元件與路由保留。代價：使用者面用語術語表改以自己為準，不再以賣家條款為唯一來源；設計文件引用的舊條號只對得上私人封存。未選：A 四頁換簡短說明、Will 寫的四份保留全文只換營運者並加示範聲明（建議）；C 全部保留全文只換營運者（他人撰寫的四頁不在同意公開的程式碼範圍）。
- **D11 品牌色**（Will 2026-10-25，兩題都照建議選 A）：互動元件用加深一階的 `#B8441F`（白字對比 5.41），原色 `#E4572E`（白字 3.68，不到 WCAG AA 的 4.5）只給 logo 與裝飾；舊公司色票換成 Hawkr 色票並改名，使用處改指語意 token，不留舊品牌色票與舊設計稿註解。實作後的補充決定（Will 2026-10-25，都照建議）：`#B8441F` 當文字放在 panel、淺橘底或半透明選取底上對比只有 3.87–4.48，這些組合改用加深的 `primaryDeep`（`#8F3315`）；暗色模式的墨綠 surface 與手寫的橄欖綠換成以 `#1F2933` 為基底的中性深色階並收進 token；admin 側欄用深色 `#1F2933`，橘色只用在選取項與主按鈕。未選：主色 B 直接用 `#E4572E`（只有大字合格）；色票 B 只改語意 token 的值、舊色票留給裝飾（仍是舊品牌素材）。對比計算腳本移到 `website/scripts/contrast.py`；它沒有接進任何關卡，且首頁季節與 Lottie 在一般電商範圍裁減後已刪，現在跑會因找不到那些 CSS 變數而 exit 1。
- **D12 素材處置 Q-A1 到 Q-A8**（Will 2026-10-26，全部照盤點的預設）：吉祥物與子品牌角色素材、影片、Lottie、QR 碼沒有一批確定有授權，全部刪除，QR 換成合成的；Iconly 與設計稿匯出的 UI 圖示刪除，兩支 App 改用 Flutter 內建 `Icons`、website 與 admin 改用 Material Symbols 的 SVG（三端圖形一致、授權只有 Apache-2.0 一份）；官方認證標章與第三方商標刪除、改文字標籤；jf-openhuninn 衍生字型保留，重新生成並改家族名，授權文件與 notice 照 OFL 保留。未選：網頁用 Lucide（三端不一致）。另（Will 2026-10-26）admin 用的 2,698 字舊子集從原始字型以同一組字元重新生成並改名，website 那份沒有程式引用的同內容子集刪除。
- **D13 賣家導覽與操作手冊**（Will 2026-10-27，選 C）：依 D2 換成佔位圖後每頁沒有資訊，改成文字版的手冊（內容原本畫在圖裡，文字要重寫）。未選：A 保留版面與佔位圖、之後由 e2e 截圖補回（建議；補回之前這幾頁沒有內容）；B 下架手冊與導覽（作品集少了賣家教學）。計畫寫 C 成本最高。
