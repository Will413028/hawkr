# 使用者面用語術語表（zh-TW → en）

> **本表是面向使用者的用語的 SSOT。** 買家與賣家介面（website、buyer-app、seller-app）、伺服器產生的文字（`LocalizedMessage`、通知、email）、共用文案目錄與法律文件，都用本表的詞；與本表不一致時改文字，不改本表。
>
> 決策：`docs/adr/2026-10-17-multi-locale-architecture.md`；來源與論證：`docs/plans/2026-09-29-a3-buyer-seller/step10e-L-brief.md` Q5、`step10e-i18n-brief.md` I7、`step10e-L0-copy.md`（Will 2026-10-17 核可）。賣家面的中文也以本表為準（法律文件已換成作品集說明，不再是用語來源）。
>
> 範圍：只收錄面向使用者的詞。Go 的內部識別字不改名；註解用本表的詞。admin 只有 zh-TW，用同一套中文詞（視角差異用 `staff` 受眾）。英文在 `en` 發佈前由 Will 審。

## 商家名單（admin）

admin 只有 zh-TW；en 欄只供契約與文件對照。

| zh-TW | en | 定義 | 使用處 |
|---|---|---|---|
| 站外業者 | prospect | 尚未加入平台的目標賣家；頁面標題、側欄與「查無此站外業者」用這個詞，頁內句子簡稱「業者」（契約與伺服器句子的說法） | admin 商家名單頁、側欄 |
| 進行中 | active | 業者的狀態：可以編輯、聯絡追蹤，會出現在採購候選搜尋、統編對帳與疑似重複清單；不叫「營運中」 | admin 商家名單、伺服器句子 |
| 已封存 | archived | 業者的狀態：從候選搜尋與清單消失、欄位僅供檢視，可以還原為進行中（圖片與詢價連結不會回來） | 同上 |
| 已入駐 | converted | 業者的狀態：已轉成平台上的店家 | 同上 |
| 聯絡方式 | contact point | 業者的電子郵件、電話、網站或社群帳號；同一種類型可以有多個 | admin 業者表單、相符業者對話框 |
| 主要 | primary | 同一種類型有多個聯絡方式時選定的那一個：主要的電子郵件用來寄詢價邀請，主要的網站給採購搜尋 | 同上 |
| 不是同一家 | not the same business | 管理員確認兩個相符的業者是不同的業者；之後不再因為它們相符而提醒，沒有取消的方法（合併會撤銷） | 相符業者對話框、疑似重複清單 |

## 治理

| zh-TW | en | 定義 | 使用處 |
|---|---|---|---|
| 措施 | enforcement action | 平台對賣家帳號或店家做的決定，種類有警告、停權、終止合作、內容下架（警告與內容下架不是限制，所以不用 restriction） | 賣家中心、seller-app、admin 的措施頁；通知；`MeasureKind` 等目錄名詞 |
| 措施與申覆 | Enforcement and appeals | 賣家端與 admin 的導覽名稱 | 賣家中心、seller-app、admin 側欄 |
| 警告 | warning | 措施的一種，不限制營運，記錄在案 | 同上 |
| 停權 | suspension | 措施的一種，期間內店家不公開、不能營業 | 同上 |
| 終止合作 | termination | 措施的一種，終止賣家與平台的合作並關閉店家；有申覆期間。狀態文字「合作已終止」= Partnership terminated | 措施頁、通知 |
| 內容下架 | content takedown | 措施的一種，讓店家指定的內容（貼文、留言、討論區留言）不再公開；立即生效、沒有結束時間，不限制營運，也不影響店家的曝光；內容只能由撤銷或申覆成立恢復。| 措施頁、社群內容的處置、通知 |
| 貼文、留言、討論區留言 | post, comment, forum entry | 社群的三種內容，也是內容下架的對象種類（`ContentKind`） | 措施頁、社群內容 |
| 預告終止 | notice of termination | 預告期間後才生效的終止合作 | 同上 |
| 定期複審 | periodic review | 沒有固定結束時間的停權，由平台定期檢查是否繼續 | 賣家端措施效果句、admin 複審期限 |
| 事由 | ground | 終止合作或風險措施的依據類型 | 同上 |
| 認定 | finding | 平台對通報或事實做出的判定，措施依據它；可被撤銷 | admin 措施詳情；賣家端措施依據的說明 |
| 檢舉 | report | 買家或公眾向平台指出店家、商品或內容違反規範；給買家、賣家看的按鈕、表單、通知與伺服器句子用這個詞 | 「⋯ → 檢舉」選單、使用者政策 §十五、「我的檢舉」、通知 |
| 通報 | report（後台） | 後台對一筆檢舉的稱呼：一位檢舉人的一次送出；只用在 admin（`staff` 受眾），買家與賣家看到的一律是「檢舉」 | admin「商家通報」、案件頁 |
| 補充 | additional information | 同一位檢舉人在去重期間內再次送出、併入原本那一筆的內容 | 伺服器句子、admin、「我的檢舉」 |
| 詢問 | inquiry | 平台對案件的賣家（之後也可能是檢舉人）的一次要求，有期限與一則回覆；種類有提供紀錄、請說明。不叫「要求」，避開申覆、解除請求 | admin 案件頁、伺服器句子；賣家端畫面在 10f |
| 不轉報 | not referred | 食安案件標記不轉報主管機關並寫原因（例如主管機關已經介入）；標記之後不能再記錄轉報 | admin 案件頁、伺服器句子 |
| 追蹤日期 | follow-up date | 轉報之後預計向主管機關確認回覆的日期（台北日期，預設轉報日加 30 天）；只顯示在案件上，不進待辦 | admin 案件頁、伺服器句子 |
| 主管機關的回覆 | authority reply | 主管機關對轉報的回覆（移送通知與結果通知可以是兩則），管理員記下收到的日期與內容；不叫「回函」，避開主管機關來函 | admin 案件頁、伺服器句子 |
| 主管機關來函 | authority order | 主管機關給平台的公文：限制商品、調取資料、暫停帳號等；不是通報，也不是「主管機關的回覆」（那是主管機關對轉報的回覆） | admin 來函頁、伺服器句子 |
| 保存期限 | preservation period | 依法或依來函暫停個資清理的期間；來函指名的帳號或店家，個資保存到這時之後才會被關店後的清理刪除 | admin 來函頁、伺服器句子 |
| 被指名者 | named party | 來函指名的帳號或店家（不一定是賣家）；完成來函時要記下是否已告知他 | admin 來函頁、伺服器句子 |
| 申覆 | appeal | 賣家對平台的措施或決定請求重新審查（對應 DSA 第 20 條的 internal complaint-handling，面向使用者用 appeal，避免與消費者申訴撞名） | `MeasureRequestKind`；賣家中心、seller-app、admin、通知 |
| 解除請求 | request to lift | 賣家完成補救後，請求平台解除措施 | `MeasureRequestKind`；同上 |
| 代行 | delegated session（標籤）；on your behalf（句子） | 平台管理員在賣家授權範圍內替賣家操作；紀錄 = delegation log；對賣家的說明例句「This was done on your behalf by Hawkr staff.」 | admin、賣家中心的代行提示 |
| 食品安全 | food safety | 有健康風險或疑似食物中毒，或未揭露安全疑慮的商品 | 檢舉類別、平台判定類別、認定 |
| 違法或禁售商品 | illegal or prohibited goods | 違法、違禁或來源不明，而沒有健康風險的商品 | 檢舉類別、平台判定類別、認定 |
| 未經許可販售 | unlicensed sale | 依法應有的登錄、許可或資格沒有完成就販售 | 檢舉類別、平台判定類別、認定 |
| 不實或誤導資訊 | false or misleading information | 虛假資料、標示不實或誤導的商品或店家資訊 | 檢舉類別、平台判定類別、認定 |
| 假認證 | fake certification | 不實的認證、檢驗或標章 | 檢舉類別、平台判定類別、認定 |
| 仿冒商品 | counterfeit goods | 冒用他人商標或外觀的商品本身 | 檢舉類別、平台判定類別、認定 |
| 侵害智慧財產權 | intellectual property infringement | 侵害他人商標、著作權、專利或其他權利的使用；仿冒商品本身是「仿冒商品」 | 檢舉類別、平台判定類別、認定 |
| 詐欺或操縱交易 | fraud or transaction manipulation | 偽造交易、洗錢、詐欺、濫用優惠、操縱評價 | 檢舉類別、平台判定類別、認定 |
| 繞過平台交易 | off-platform transactions | 引導買家繞過平台付款或規避平台服務費 | 檢舉類別、平台判定類別、認定 |
| 不當使用個人資料 | misuse of personal data | 未經授權蒐集、利用、揭露或出售買家個人資料；「個人資料」本身不是違規的名稱，所以寫成「不當使用」 | 檢舉類別、平台判定類別、認定 |
| 冒用或誤導交易主體 | impersonation | 冒用平台名義、未經授權的保證，或讓買家誤認交易主體 | 檢舉類別、平台判定類別、認定 |
| 干擾或濫用平台 | platform abuse | 干擾或破壞平台與資訊安全、以爬蟲或自動化不當取得資料；檢舉人不能選 | 平台判定類別、認定 |
| 其他 | other | 檢舉人無法歸類時選；分案時要改判成有依據的類別，或直接設定結果；平台判定類別與認定不能用 | 檢舉類別 |
| 垃圾訊息 | spam | 社群內容中重複、無關或以廣告洗版的貼文、留言與討論區留言（買家條款訂出後補依據） | 社群內容的隱藏與內容下架的理由 |
| 騷擾或霸凌 | harassment or bullying | 社群內容中針對特定的人或店家的辱罵、威脅或持續打擾（同上） | 同上 |
| 仇恨或歧視言論 | hate or discriminatory speech | 社群內容中以身分、族群或特徵攻擊他人（同上） | 同上 |

「食品安全」到「仇恨或歧視言論」這十六列是政策分類 `PolicyCategory`（`api/hawkr/common/v1alpha1/policy_category.proto`）的名稱。前十三列是賣家治理的依據，給賣家的理由用這組名稱，賣家端的措施標題與依據顯示同一組名稱；最後三列是社群內容的類別，給買家寫的內容的隱藏與內容下架用，買家條款訂出後補依據；檢舉人選不到，認定與案件類別可以用。

## 交易與審核

| zh-TW | en | 定義 | 使用處 |
|---|---|---|---|
| 消費者申訴（發票申訴） | customer complaint | 買家對發票或訂單的申訴，與賣家對措施的請求無關 | 發票申訴流程 |
| 售後申訴 | dispute | 買家對賣家售後處理結果向平台提出的申訴（英文不用 appeal，避免與申覆撞名） | 售後流程、admin 售後爭議 |
| 補件 | provide additional information；狀態 More information needed | KYC 審核要求賣家補資料 | KYC 流程 |
| 商家認證 | seller verification | 賣家的身分及資格審核 | KYC 流程 |
| 身分認證 | identity verification | 商家認證中核對身分的那一部分 | 法律文件、個資說明 |
| 紀錄 | record | 一律寫「紀錄」，不寫「記錄」（名詞） | 全部介面 |

## 退場用語

下列詞不再對使用者顯示；Go 內部識別字不改名；註解用本表的詞。

| 退場 | 改用 | 原因 |
|---|---|---|
| 處置（指對賣家的平台措施） | 措施 | 與本表的「措施」不一致；非治理意義的「處置」（例如異常處置）不在此限 |
| 申訴（指賣家對措施的請求時） | 申覆 | 「申訴」指消費者申訴；發票申訴、售後申訴仍用「申訴」 |
| 補正（對使用者顯示時） | 解除請求（請求的種類）或修改（資料）；發票的「補正期限」改「補件期限」 | 賣家看到的是「解除請求」 |
| 處置與申訴（導覽名稱） | 措施與申覆 | 同上；伺服器句子不寫 client 的導覽名稱 |

## 維護

- 新增詞：先加在本表，再進文案目錄；本表是用語的唯一依據，修訂時同一次變更裡更新本表與目錄。
- 英文起草依本表（LLM 起草、Will 審）；未列入的詞先補表再翻。
- 搜尋框的英文提示（英文介面）：placeholder `Search in Chinese, e.g. 番茄`；零結果時 `No results. Search currently works with Chinese keywords only.`
