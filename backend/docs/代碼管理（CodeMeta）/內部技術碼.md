## WebhookProvider

- **類別**: 內部技術碼
- **介面**: CodeMeta
- **前端可見**: No
- **使用服務**: payment, payuni-webhook, shipping
- **DB 儲存欄位**: payment_webhooks.webhook_type, webhook_inbox.provider（存 Value）
- **說明**: Webhook 收件來源（**服務商分類，不限金流商**）。表級分類，回答「這筆 webhook 來自哪個服務商」。獨立於 PayUniEventType（後者表達 PayUni 內部事件子類別），抽象層級不同。
- **歷史背景**: 2026-04-08 從 `payment-service/adapter/webhook/WebhookType` plain Java enum 升級為 CodeMeta。預留未來支援其他金流商（綠界 ECPay、藍新 NewebPay 等）時新增 enum 值。 2026-09-12 起不再限於金流商：66 號 Uber Direct 的 webhook 共用 `payuni-webhook-service` 既有的 `webhook_inbox`（該表本來就有 `UNIQUE (provider, webhook_type, event_key)` 的 provider 維度），因此新增 `UBER`。
- **特殊方法**: 無

| Name | Code | Value | Label | Description |
|------|------|-------|-------------|-------------|
| PAYUNI | PAYUNI | 8241 | 統一金流 | PayUni（統一金流）所有 webhook |
| UBER | UBER | 8242 | Uber Direct | Uber Direct 即時配送所有 webhook（`delivery_status`／`courier_update`／`refund_request`）；66 §5.1.6／§6.3.4 |

> 🔴 **`webhook_inbox.provider` 存的是 Value（數字碼字串）不是 Name**：`V1__init_webhook_tables.sql` 逐字
> `provider VARCHAR(20) NOT NULL DEFAULT '8241'  -- WebhookProvider.PAYUNI`。
> ⇒ Uber 事件要寫 `'8242'`，**寫 `'UBER'` 會讓 consumer 拿字串去比數字碼**（66:950 紅字）。
>
> ⚠️ 本 enum 是 **webhook inbox 的收件分類**，與 MQ 事件 envelope 的 `provider` 欄
> （值域 `MERCHANT`／`TAQBIN`／`CVS_711`／`UBER_DIRECT`，**字串**，65 附錄 C.2 定案）**不是同一個東西**，
> 兩者不得互相填值。

  - ⚠️ **同 exchange 不是同 family 的理由**：`hawkr.shipping` 上本來就有多個 publisher（36 §1.4 禁止的是「同一條 routing key 多個 publisher」）。碼表的邊界錨在 **owner domain ＋ routing key 前綴**，不是 exchange。
- **值域邊界（兩條）**:
  1. routing key 以 **`logistics.`** 起頭者屬本家族，不論 publisher 是哪個服務。🔴 `logistics.cost.incurred` 的 producer 是 **shipping-service**（「這趟配送 provider 成本多少」是 shipping domain fact，70 §7.1）——publisher 服務**不是**本家族的判準。
  2. ⚠️ **只收本 repo 真正落碼的 routing key**。70 §7 的線 B 共三條（`logistics.cost.incurred`／`logistics.receivable.settled`／`logistics.receivable.unconfirmed`），本表目前**只有第一條**——其餘兩條的 producer **尚未實作** ⇒ 先收進來會造出「有碼值但沒有人發得出這條事件」的幽靈值。**由各自的 owning WP 落碼時同批擴充。**
