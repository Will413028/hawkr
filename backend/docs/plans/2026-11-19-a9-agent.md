## 前提（核對日 2026-11-19，dev `bc2c732c`）

- **會改到或取代的部署是否在線**：不在線。系統從未上線；不受回滾窗口、資料搬移、雙跑約束，舊資料不搬。
- **與 A3／A6 的關係**：沒有共用模組，但不是零依賴【量，`interface-inventory.md` §5】。ai-service 經單體的 `legacy/buyerserver`、`legacy/sellerserver` 呼叫 buyer、seller 的 4 支方法（`GetBuyerEntitlement`、`GetSellerStats`、`BatchGetSellerMeta`、`SearchSellerProspects`）；搬進單體後改 in-process 呼叫，seller 已預留（`internal/modules/seller/CARRYOVER.md:170`）。A3 改這些方法的簽章時，A9 的呼叫點跟著改。A6 只有間接關係（評分經 `GetSellerStats`）；4 個採購 e2e spec mock 了 `/app/chat/*`，A6 改聊天契約時要一起更新。A9 不改 buyer、seller、review、im、crm 模組的程式碼；需要它們新增方法時停下回報。
- **ordering、catalog 仍在 Java**（B8 之前）：A9 期間經 `internal/legacy` 的 client 呼叫，模組只依賴 port。
- **pricebook 已刪，不接回**（ADR `2026-10-27-general-ecommerce-scope-cut.md` D2）：只解析到平台分類樹與 LLM 召回，報價只看供應商報價。已確認【量，`domain-inventory.md` §4.1：資料與程式已清乾淨，殘留的是命名與 prompt】。
- **LLM provider 是外部呼叫**：不在 DB transaction 內呼叫（單體規則 5）；CI 與本機測試用替身，不打真的 provider（主計畫全域約束）。
- **串流時長**（A9-0 spike，`spikes.md` §2；Will 2026-11-19 確認）：單體與 App 不限串流總時長；website 經 Vercel 外部 rewrite，上限 120 秒，文件沒排除它算總時長【文件，未實量】。所以單體的每條 server stream 在 100 秒時正常結束，client 用 A9-D4 的游標重連續看；一輪的總時長不受這個上限約束。單輪上限照 gateway 現值 120 秒，由單體自己設（gateway 刪除後沒有別處保證）。
- **工具鏈**（預設，可推翻）：照根目錄 `AGENTS.md`。

**驗收基線：** A9-0 對當時 HEAD 跑單體、gateway、ai-service 的 unit 測試，記在文末「基線」；既有失敗不在本階段修。integration 與 e2e 不在本機跑，推上去看 CI。CI 一次只推一批。
