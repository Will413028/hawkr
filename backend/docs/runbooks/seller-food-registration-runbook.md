# 食品業者登錄審核 runbook

賣家送出食品業者登錄字號後，管理員人工對照食藥署的登錄資料核准或退回；核准的那一筆才會顯示在店面與商品頁、並開放上架加工食品。模型與狀態見 `internal/modules/seller/AGENTS.md`「食品業者登錄」，決策見 `docs/plans/2026-09-29-a3-buyer-seller/step10d-d3b-decision-brief.md`，核對標準見設計書 18 §10。

## 1. 收件匣

- 後台「食品業者登錄審核」（`ListFoodRegistrations`，權限 `seller.food_registrations.list`）預設（`inbox` 為 UNSPECIFIED 或 `DECIDABLE`）只列現在可以裁定的件：營運中店家的待審件、店家的實名認證 KYC 已核准，送出時間舊到新；每筆的 `can_approve` 表示現在能不能核准。排序鍵（送出時間與 id）不會變，KYC 狀態只是篩選條件：翻頁途中同一隊列的件不會重複或漏掉；店家的 KYC 在翻頁途中核准，件離開 `AWAITING_KYC`、進入 `DECIDABLE`，位置在已翻過的游標之前的這一輪不會再翻到，重新載入即可。
- 還在等 KYC 核准的件（沒申請、草稿、審核中、已退回）在 `inbox = AWAITING_KYC` 的隊列：可以先看與退回，**不能核准**（`DecideFoodRegistration` 回 failed_precondition）；等 KYC 核准後它會出現在預設的隊列。歷史（指定 `state` 為 PENDING 以外）不可以同時指定 `inbox`。
- 已關閉或等待刪除的店家不在收件匣，裁定回 failed_precondition；關店不撤回待審的件，店家在退場（關店 30 天後；因終止合作而關閉的到申覆期限）之前重開同一家店時，待審的件照常有效。

## 2. 審核步驟

1. 開單筆頁（`GetFoodRegistration`，權限 `.get`）：看送出的字號、目前核准的字號、KYC 狀態與主體（企業：公司名稱與統編；個人：real_name）。主體只在 KYC 已核准時顯示；KYC 還在草稿、審核中或被退回時只顯示狀態。
2. 按頁面的「在食藥署查詢」開食藥署的食品業者登錄查詢頁，以字號查詢。**查詢頁顯示哪些欄位尚未驗證**，上線前人工查一次再定稿本頁。
3. 核對標準（`DecideFoodRegistration`，權限 `.decide`）：
   - 查得到這個字號，而且登錄狀態有效；
   - 企業賣家：登錄的業者統編或名稱與 KYC 的統編、公司名稱相符；
   - 個人賣家：查詢結果有顯示業者名稱或負責人時，與 `real_name` 相符；不顯示時只核對字號有效，內部註記寫「僅核對有效」；
   - 不符就退回，理由必填（賣家看得到，寫明哪裡不符、要賣家確認什麼）；內部註記只給後台看。
4. 核准：新字號成為店家公開的字號，舊的核准同時結束（`SUPERSEDED`）；店面與商品頁的快取在同一個 transaction 內排入失效。

## 3. SLO

待審的件 **7 個日曆天內** 裁定，從可以裁定時起算（送出與商家認證核准兩者較晚的那一刻；等商家認證的期間不算在平台頭上）（內部 SLO，不寫進契約與條款；比照措施補正，見 `seller-violation-management-runbook.md` §5.2）。「待審核」分頁依期限由近到遠，期限也顯示在清單、詳情與待辦頁。審核期間目前核准的字號照常有效，賣家不會因為等待而失去登錄。

## 4. 賣家端的動作

- 送出（`SubmitFoodRegistration`）：已有待審時，字號相同沿用、不同則取代（舊的撤回）。
- 撤回（`WithdrawFoodRegistration`）：只撤回待審，核准的保留。
- 清除（`ClearFoodRegistration`）：結束核准的並撤回待審，立即生效，店面與商品頁不再顯示字號。
- 送出時字號與目前核准的相同，不建立新登錄（有待審的就撤回它）。
- 裁定時發 `FoodRegistrationDecided`（帶字號與退回理由）；賣家通知是 A8 的 notification 的工作，目前還沒有訂閱者，賣家在錢包看狀態。
- 送出時要確認〈食品業者登錄個人資料蒐集告知事項〉（`FOOD_REGISTRATION_NOTICE`）；建立新登錄時紀錄綁定那一筆登錄。
- 店家退場（關店 30 天後，之後不能重開）時，待審的件撤回（`WITHDRAWN`）、仍核准中的結束（`STORE_RETIRED`）；關店 6 個月（184 天）的個資清理時，全部登錄的字號、退回與撤銷的理由、內部註記清掉；審核紀錄（不含字號）保存到關店後 2 年再刪除，告知同意紀錄一起刪。

## 4a. 撤銷

核准後發現字號冒用、不實或與食藥署資料不符時，在單筆頁按「撤銷登錄」（`RevokeFoodRegistration`，權限 `seller.food_registrations.revoke`）：給賣家的理由必填，不帶內部註記（核准時寫的註記留著，單筆頁標「核准時的內部註記」）；店面與商品頁立即不再顯示這個字號，賣家看到「已被平台撤銷」與理由，重新送審即可（不另設申覆）。撤銷是更正單一資訊，與措施不連動：冒用或不實登錄另外記違規認定（`FAKE_CERTIFICATION`）並依認定下措施；店家若有同一字號的待審件，撤銷不會自動退回，另外裁定。

## 5. 觸發條件

食藥署釋出逐家登錄資料的 API 或開放資料時，人工核對改成自動比對，並對核准過的字號做週期複查。
